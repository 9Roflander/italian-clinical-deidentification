# Italian Clinical De-identification with Small Language Models: Code, Configurations and Results

Code, configurations, prompt templates, frozen folds, synthetic training data and all evaluated runs for the paper
*Ciao, [NOME]! Synthetic Data, Style Anchoring and Output Format for Italian Clinical De-identification with Small
Language Models* (under review at NLPIR 2026).

The study compares three systems for finding names, ages, dates and places in Italian clinical notes, using 82
annotated notes and 5-fold cross-validation:

| System | Model | Output |
|---|---|---|
| S1 | Llama-3.2-3B-Instruct, QLoRA | the whole note as labelled segments |
| S2 | Llama-3.2-3B-Instruct, QLoRA | only the sensitive strings, placed by a fixed locator |
| S3 | `dbmdz/bert-base-italian-xxl-cased` | BIO token classification |

Each system is trained on three arms: E1 gold notes only, E2 gold plus non-anchored synthetic notes, E3 gold plus
style-anchored synthetic notes. E8–E10 are exploratory BERT arms.

## What is in this repository

| Path | Contents |
|---|---|
| `src/` | Data, generation, training, encoder, evaluation and provenance code |
| `tests/` | Automated tests |
| `configs/`, `prompts/` | Generation, training and evaluation settings; versioned prompt templates |

| `synthetic_data/fold_*/non_anchored/examples.jsonl` | The 1,484 accepted **non-anchored** synthetic notes (text and span annotations), generated by `gemini-3.8-flash` |
| `synthetic_data/fold_*/*/` | Generation plans, request logs (hashes and token counts, no text), validation and audit reports for both arms |
| `experiments/clean_cv/` | Llama runs: S1 (E1–E3) and S2 (E1–E3; E2 also with seeds 43 and 44) |
| `experiments/baselines/` | BERT runs: final configuration (E1, E2, E3, E8, E9, E10, seeds 42–44) and the first configuration (E1, E3) |
| `experiments/comparisons/` | Paired bootstrap differences between runs |
| `experiments/development/` | Evaluator dry runs and generation pilots |
| `experiments/training_records/` | For each of the 28 runs and each fold: the training manifest (configuration, package versions, per-step losses, update budget, trainable parameters, peak GPU memory, adapter or model hash) and the training log. `datasets/` holds the exact training example list of arms E1–E3 for each fold (example IDs, repeat index and SHA-256 hashes of input and target, no text); every system used the same list for the same arm and fold. The lists of E8–E10, subsets of E3, are identified by `dataset_sha256` in their training manifests |
| `audit/` | Analysis plan (`PREREGISTRATION_2026-11-10.md` and addendum), evaluation protocol, data provenance, leakage report, known problems of the earlier pipeline |
| `colab/` | The Google Colab notebooks used for training (outputs cleared), `build_transfer.sh`, `check_status.py` |
| `scripts/` | Smoke tests with tiny random models; `paper_numbers.py`, which recomputes the numbers of the paper |

Every run folder holds pooled, per-fold, per-category and per-note metrics, error breakdowns, bootstrap intervals and a
run manifest (code commit, configuration, package versions, hashes of the predictions it was computed from).

## What is not in this repository, and why

| Not included | Reason | How to obtain |
|---|---|---|
| Text of the 82 gold notes | They come from the dataset of Miranda et al. (CLiC-it 2025), which has no licence file | Rebuilt from the public source by `src.data.build_gold` (below) |
| Style-anchored synthetic notes (1,488) | They were generated with masked real notes in the prompt; releasing them needs a separate risk assessment | Only metadata is included. Arms E3 and E8–E10 cannot be retrained from this repository |
| Model outputs (`predictions_secure/`) | They contain note text | The run folders keep their hashes and all metrics derived from them |
| Fine-tuned weights | Size | Not distributed |
| Code of the earlier pipeline (`original_work/`) | Contains historical data | Described in `audit/` |

## Setup

Python 3.12.

```bash
python -m venv .venv-gen
.venv-gen/bin/python -m pip install -r requirements-generation.txt
```

Training uses `requirements-training.txt` (`requirements-training.lock` records the exact Colab environment).

## Rebuild the gold standard

```bash
.venv-gen/bin/python -m src.data.build_gold      # downloads the source CSV (pinned commit e8609c92 and SHA-256) and builds gold v1
.venv-gen/bin/python -m src.data.build_gold_v2   # applies the reviewed corrections in data_manifests/ and builds gold v2
```

Both files are written to `data_secure/gold/`, which is git-ignored. The rebuilt files match the SHA-256 values
recorded in `audit/results/gold_v2_build_summary.json` (checked on 2026-11-11). In this public copy,
`src/data/build_gold.py` skips one comparison with a historical file that is not published. The comparison only fills
the `old_gold_relation` column of `data_manifests/gold_quality_report.csv` and does not affect the gold files.

## Tests

```bash
.venv-gen/bin/python -m pytest tests -q
```

Run the tests from a git clone, because several of them check git-ignore rules and commit provenance. In our check,
on a copy that was not a git clone, 903 of 914 tests passed after rebuilding the gold standard. The other tests either
need a git clone or compare against the historical code and data, which are not published.

## Training

The notebooks in `colab/` ran the training on Google Colab (NVIDIA L4). They expect a transfer archive built by
`colab/build_transfer.sh` from a local checkout that holds the rebuilt gold standard and the synthetic notes. Arms E1 and
E2 can be rebuilt from this repository; E3 and E8–E10 need the style-anchored notes, which are not published.

## Results

```bash
python scripts/paper_numbers.py
```

prints the numbers of Tables 2 and 4–8, Fig. 1 and Sections 3–7 of the paper from the files in this repository. It
needs neither the gold notes nor the model outputs. Training times are the elapsed minutes at the last optimizer step in
each training log. Fold 5 of S2 E2 seed 42 was interrupted and run again from the start; both logs are kept.

Strict exact-span micro-F1, pooled over the 82 out-of-fold notes. Brackets give 95% paired document bootstrap
intervals (10,000 replicates, stratified by fold).

| Micro-F1 | E1 (gold only) | E2 (+ non-anchored) | E3 (+ style-anchored) |
|---|---|---|---|
| S1, seed 42 | 0.588 [0.490, 0.686] | 0.614 [0.520, 0.706] | 0.611 [0.512, 0.710] |
| S2, seed 42 | 0.652 [0.576, 0.724] | 0.722 [0.650, 0.790] | 0.668 [0.584, 0.746] |
| S2, mean ± sd, seeds 42–44 | — | 0.709 ± 0.013 | — |
| S3, seed 42 | 0.573 [0.495, 0.653] | 0.750 [0.682, 0.811] | 0.630 [0.552, 0.706] |
| S3, mean ± sd, seeds 42–44 | 0.559 ± 0.036 | 0.710 ± 0.092 | 0.655 ± 0.051 |

The pre-specified comparisons and the decision rule are in `audit/PREREGISTRATION_2026-11-10.md`, and their results in
`experiments/comparisons/`. All 82 notes are development data: there is no independent test set, and the revised
annotations were made by one annotator.

## Synthetic data: notes on use

- Notes were generated per fold with `gemini-3.8-flash` (the version string returned by the API for every request),
  three cases per request. Each note was validated automatically (`src/generation/`) and audited for overlap with the
  test notes of its fold (`post_audit_report.json`). No accepted note shares a run of more than eight words with any
  test note of its fold.
- The non-anchored prompt contained no real note. We nevertheless checked the released notes against all 82 gold notes:
  - 11 of the 1,484 notes share one or two 8-word sequences with a gold note;
  - 90 contain one of 13 gold person names of four or more characters;
  - 3 contain a multi-word place name that also occurs in the gold notes.
- The notes were generated by a language model from case specifications. They were not reviewed by a clinician and
  must not be used as clinical information.
